# ADR-002: BaseScraper retornando RawJob e Greenhouse via API JSON pública

## Status
Aceito — implementado em 2026-10-05

## Contexto
Era a primeira etapa real de coleta. Duas questões de design não respondidas pelo PRD:

1. **O que os scrapers retornam?** O pipeline prevê um `Normalizer` que "converte diferentes formatos para GameJob" (docs/prd.md:298), o que implica que a saída dos scrapers **não** é `GameJob`.
2. **Como extrair dados do Greenhouse?** O site é renderizado em HTML, mas a plataforma expõe uma API JSON pública.

## Decisão
- **`src/models/RawJob.ts`**: modelo bruto intermediário entre scrapers e Normalizer. Campos principais obrigatórios (`title`, `company`, `location`, `description`, `url`, `source`) e opcionais (`postedAt`, `salary`, `tags`). Tipado como `string`/ISO para datas — a conversão para `Date` e o preenchimento de campos derivados (`role`, `engines`, `seniority`, `hash`) ficam no Normalizer.
- **`src/scrapers/BaseScraper.ts`**: classe abstrata com `source` (string readonly) e `scrape(): Promise<RawJob[]>`. Fornece `fetchJson(url)` protegido com `User-Agent: GameJobBot/1.0` (padrão já usado em `src/test-scraper.ts`) e `Accept: application/json`. Erros de HTTP lançam exceção com status e URL — o tratamento "um scraper falha, os demais seguem" é responsabilidade do futuro ScraperManager, não do scraper.
- **`src/scrapers/GreenhouseScraper.ts`**: usa a **API JSON pública** `boards-api.greenhouse.io/v1/boards/{board}/jobs?content=true` em vez de parsear HTML. Recebe os tokens dos boards (empresas) via construtor. `content` (HTML da descrição) é convertido para texto puro por `stripHtml` simples (regex + entidades básicas). `company` é derivado do token do board, já que a API não retorna nome da empresa.
- **Testes com `fetch` mockado** via `jest.fn<typeof fetch>()` de `@jest/globals` (ambiente ESM não tem `jest` global).

## Consequências
- Positivas: sem dependência de parser HTML (cheerio/jsdom) para o Greenhouse; `RawJob` dá ao Normalizer um contrato estável mesmo com scrapers de formato heterogêneo (RSS do WorkWithIndies, HTML do Itch.io); testes rápidos e determinísticos sem rede.
- Negativas: `RawJob.company` fica sendo o token do board (ex: `"ubisoft"`) até o Normalizer ter um mapeamento ou o scraper aceitar nome de exibição; `stripHtml` é propositalmente simples — se descrições quebrarem, avaliar biblioteca dedicada.
- Alternativas rejeitadas: scrapers retornando `GameJob` direto (anularia o Normalizer, previsto no PRD); parsear HTML das páginas públicas do Greenhouse (frágil a mudança de layout; a API é estável e documentada por uso).
